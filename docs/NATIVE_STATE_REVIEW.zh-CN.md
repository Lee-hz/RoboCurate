# 真机遥操作：画面与机器人反馈联合审核

本轮优先处理 G1 原始 MCAP。新增的是不训练模型权重的输入组织和校验流程，使用现有公司 MiniMax 服务。仿真状态支持仅作辅助，不能代替真机验证。

## 已实现

- “范本审核”新增 **画面＋机器人反馈** 与 **纯视觉对照**。打开反馈预览只进行本机读取，提交分析后才将所选画面和摘要发到公司模型。
- 从原始时间戳读取身体关节、双手反馈及 IMU 角速度。控制指令、参考根部位置、物体位置、任务成功标志均不进入此版状态摘要。
- 以 20 Hz 因果对齐反馈；超过 150 ms 的陈旧样本及无效数据不补成有效状态。四指闭合量使用食指、中指、无名指、小指的反馈中位数，保留原单位。
- 用实测关节及 G1 URDF 计算腕部关节原点相对骨盆的轨迹，提供变化候选和简短摘要。它不是标定后的 TCP，也不含机身的世界位移。
- 显著手指变化、腕部运动和下肢/身体角速度变化帮助选择画面。仍保留均匀覆盖，单次观察预算为最多 16 张，真机可分配给头部及双腕相机。
- 发现明显张开变化后，可将结果观察延长至后续帧，上限为 10 秒；下一次明显闭合候选会限制跨尝试取证。候选不是语义阶段或失败标签。
- 增强模式要求每个条件明确标注可观测性：直接可核对、受限或未知。后两类不能直接判通过。跨越下一次闭合候选的结果证据会被剔除并保留复核说明。
- 每段可查看状态摘要、变化候选和不同相机的证据。模型判断、规则降级及人工复核分别保存。

输入只有视频或状态缓存缺失时，页面会明确提示，并保留视觉分析。不能把缺失反馈写成“手没动”或“动作已完成”。

## 解释边界

1. 手指闭合不证明握到了物体，张开也不证明物体进入了容器。
2. 腕部相对机身运动不代表它相对桌面或世界的轨迹；身体角速度也不能证明平移或安全撤离。
3. 变化检测使用平滑、滞回和持续时间阈值，这些是当前工程初值，不是成功区间或质量合格线。候选时刻不能当作精确接触时刻。
4. 受遮挡时，仅看到物体颜色透过筐壁不能确认空间包含；后来看到物体在筐外，也不能独自证明“先入篮后掉出”。
5. 模型自报可观测性也可能出错。因此程序约束减少的是无依据的通过，并不能替代人工真值评测。
6. 四指中位数适合当前包夹动作的粗变化检测，不能覆盖所有多指操作。尚未核实的单位或通道只报告缺失/读数变化，不套用真实手的闭合规则。

## 本轮真机对照

使用原始 `episode_000131` 的 23.0–30.842835583 秒，对同一任务定义分别运行纯视觉和反馈增强模式。该片段用于开发联调，不是独立测试集。结果保存在 `workspace/taskflow/native-ablation/`。

两种模式共用基础数据校验：亚帧级无画面间隙保留为未知区间；只有范围端点不超过 1 ms 的小数舍入才允许修正并记录原值。目标条件可以引用请求中明确提供的后续观察帧；不能引用不存在、属于范本或越过允许观察范围的证据。

检查窗口可以通过 `/api/taskflow/jobs` 的 `start_s`、`end_s` 指定；省略则检查整段。报告始终标明实际检查范围，其余时间不能宣称已审核。

## 如何验收效果

`workspace/taskflow/native-evaluation/annotation-queue.json` 是其余 17 条原始真机记录的待标注清单。闭合—张开—再次闭合模式只用于挑出需要优先回看的窗口，不能自动标成抓取失败。所有人工标签初始均为空。

人工需确认同一任务定义版本、每次尝试的阶段区间和目标结果。已反复调试的 131 号记录不放进这份候选队列；同一采集批次仍不能代表跨场景泛化。

使用人工填写的 `label-template.json` 和两种模式导出的运行 JSON：

```bash
.venv/bin/python scripts/evaluate_taskflow.py --labels human-labels.json --runs visual-run.json state-run.json --output comparison.json
```

评测器拒绝未人工确认、数据源不一致或任务定义版本不一致的标注。它不使用人工修正过的预测结果来抬高模型成绩。关注失败误判通过、失败检出、证据不足比例、段级匹配和边界误差；没有失败样本时，失败相关指标返回空值，不返回“0%误判”。

目前没有独立人工标注集，因此不能从单例联调或软件测试声称准确率提高。输入策略、观测可见性约束和多相机是本轮组合改动，若要判断每个因素的贡献，还需要分开做消融实验。

## 论文来源与适配范围

参考 [ProTracer: Proprioception-Guided Failure Diagnosis in Robot Manipulation](https://arxiv.org/abs/2609.21369) 的“机器人状态选关键时刻＋状态叙述＋视觉核查”思路。本实现是 G1 多指手与移动操作的工程适配，使用去抖和滞回变化检测，没有宣称复现论文的完整变点优化器或论文准确率。
