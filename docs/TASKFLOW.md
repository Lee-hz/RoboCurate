# 范本驱动的任务审核

入口：启动工作台后，打开侧栏 **范本审核**，或 `http://127.0.0.1:8421/#taskflow`。

新增真机反馈增强：可在“画面＋机器人反馈”和“纯视觉对照”之间选择，查看真实手部、关节变化与多相机证据。[说明与验收方法](NATIVE_STATE_REVIEW.zh-CN.md)。

## 使用顺序

1. 选择已有采集记录并加入工作流，或上传任务视频，也可以填写本机视频路径。
2. 选择范本，填写必要的任务要求，点击 **解析范本**。模型先识别任务目标、对象和阶段类别，然后切分范本并逐段核查。范本本身不被假定为全程成功。
3. 在 **查看任务定义** 中检查并修改名称、目标和完成条件；可以添加、删除阶段。
4. 选择同类任务的待审录像，点击 **自动审核**。录像中的阶段顺序、次数和时长由画面决定，不要求与范本一致。
5. 点击时间线或片段列表，查看每条完成条件的结果和证据画面。可点击证据跳到对应时刻。
6. 使用 **人工复核** 修正完成结论；使用 **修订分段** 调整边界、类别，拆分或合并片段。人工结果和模型结果分别保留。
7. **导出 JSON** 保存任务定义版本、时间区间、模型判断、人工修订、证据索引和采样说明。这是审核标注，不是特定训练框架的数据包。

## 判断含义

- **已完成**：模型判断该阶段的所有完成条件都有所提供画面支持。
- **未完成**：至少一个条件被判失败，并引用了所提供的画面。
- **证据不足**：缺少条件、结果被遮挡、动作在录像结束时仍未完成，或没有可核对的证据。

程序检查证据是否来自当前录像、时间是否对应、条件是否齐全，但不能以这些检查证明视觉判断必然正确。遮挡、小物体、误识别仍需人工检查。模型不是经过本任务准确率验证的合格判定器。

失败后重试保留为不同片段；最后一次成功不覆盖先前失败。连续动作跨越粗分段窗口时会重新合并核查，避免把窗口末尾当作失败。页面给出的是各片段计数，不把它伪装成整条任务的合格率。

## 个人 MiniMax 接入

每个人下载项目并在自己的电脑启动。右上角 **MiniMax 接入** 中填写完整 HTTPS Chat Completions 地址（以 `/chat/completions` 结尾）和自己的 API Key，点击 **保存接入**。模型固定为公司提供的图像模型 `HORIZON-MiniMax`，不支持用任意官方 MiniMax 文本模型替换，不自动回退到 OG。

- 保存配置不调用模型或消耗推理额度。状态“待首次调用验证”表示格式已校验；首次任务成功后显示已连接。
- API Key 不回显、不写入浏览器存储。保存在 `workspace/taskflow/minimax-local.json`，文件权限 `0600`；采用原子替换保存，目录及密钥文件被源码包排除。
- 同地址留空 API Key 可保留原凭据；更换地址必须重新填写，防止把旧凭据发送到新服务。
- 断开接入清除该接入文件内的密钥并写入禁用标记，不会悄悄使用旧配置继续调用。历史 `company-vlm.json` 和外部凭据文件不删除。
- 有排队或运行中的任务时不能切换凭据，包括尚在结束当前请求的取消任务。
- 保存的个人接入优先于旧文件配置。没有个人接入文件时，兼容 `ROBOCURATE_VLM_CONFIG` 或 `workspace/taskflow/company-vlm.json` 指定的本机配置；新任务仍仅允许 MiniMax。
- 不创建网站账号；服务只监听本机回环地址。源码更新取消旧启动器默认开放局域网的方式。

历史文件配置示例（仅占位符，不要提交实际配置）：

```json
{
  "label": "MiniMax",
  "protocol": "chat_completions",
  "endpoint": "https://YOUR-COMPANY-GATEWAY/v1/chat/completions",
  "model": "HORIZON-MiniMax",
  "allowed_models": ["HORIZON-MiniMax"],
  "api_key_file": "/absolute/private/path/company-vlm.key",
  "requires_auth": true,
  "max_output_tokens": 32768,
  "timeout_s": 360,
  "compact_frame_ids": true,
  "cache_responses": true
}
```

旧 OG 结果保留真实模型来源，不改名为 MiniMax。个人接入不会修改已有范本、模型结果或人工复核。

2026-10-16：整段真机审核曾在 12000 token 上限处截断（推理占用了大部分额度，最终 JSON 不完整）。本机已将 `max_output_tokens` 调为 32768，仍拒绝截断结果、不补造判断。较长审核会分多个区间请求，界面显示当前步骤和已用时；失败可从主页面恢复原设置后重试。

本机还开启 `compact_frame_ids: true` 与 `cache_responses: true`：发给模型的是简短画面编号，返回后转换为原始证据 ID；相同模型、任务说明及图像内容可以复用已保存响应。缓存按图像字节指纹区分，任务条件或画面变化会重新分析。调用记录中保留缓存标志、原响应时间和画面编号映射。需要强制重新推理时，将 `cache_responses` 设为 `false`；重新启用后可继续复用缓存。

没有有效接口时不生成模拟预测。页面的“图像接口已连接”表示该配置曾成功返回结构化图像响应，不代表所有录像都能稳定分析，也不代表已测出任务识别准确率。单次分析可能发起多次模型请求并消耗公司服务额度。

## 数据与限制

- 视频：MP4/MOV/MKV/WebM/AVI/M4V，需要系统 `ffmpeg` 和 `ffprobe`。上传上限 1 GB，时长 0.2 秒至 60 分钟；长视频建议按任务拆分。
- 现有 MCAP：默认使用头部相机；双目并排画面只取左眼。反馈增强模式会读取有效的关节、手部和角速度反馈，并按预算选择多路相机画面。
- 已导入证据快照：使用本机缓存帧。仿真快照通常为 2 Hz；无法从缓存恢复原始帧率。
- 当前整段粗分析最多 16 帧，局部核查最多 16 帧（短候选片段会组成最长 8 秒的观察窗口），跨窗口复核最多 16 帧。页面记录实际采样间隔；长录像和快速动作可能遗漏。片段边界是估计，视频 seek 时间不是经过认证的帧 PTS。
- VLM 使用图像内容判断可见结果，不从单目画面虚构厘米级距离、碰撞力或安全认证。需要这些指标时仍需标定、物体位姿和传感器证据。
- 画面会发送到配置的公司模型接口。原始文件、审核数据库、抽帧、请求说明及模型响应保留在本机 `workspace/taskflow/`；不会上传整条 MCAP。
- 数据源指纹用于检测本机文件是否变化，不是密码学级内容完整性认证。任务定义更新后，旧结果保留当时的定义快照，并显示版本变化提示。
- 修订分段会使旧完成判断不再适用；新段待人工复核。原始模型结果及历史修改留在数据库中，JSON 导出也保留原始模型分段。
- 服务重启后未完成的任务显示“已中断”，需要重新提交。暂不支持跨进程并行运行多个工作流服务器。

## 验证

```bash
.venv/bin/python -m pytest tests/test_taskflow.py tests/test_sim_segments.py tests/test_stage_evidence.py tests/test_execution_quality.py -q
node --check static/taskflow.mjs
```

测试使用独立临时数据库和合成视频；伪造模型响应仅用于单元测试，不写入实际工作空间。真实 VLM 联调记录保存在本机，不随源码发布。需要独立人工标注集，才能测算分段边界误差、阶段识别准确率及目标完成判断的漏检/误报率。
