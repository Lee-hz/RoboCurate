# VLM 真机任务审核工作台

更新：2026-10-16。用户最新明确：产品主题是 VLM。旧技术质检方案未达到数据分级筛选效果，已被上级否定；后续不再以传统质检、数值阈值或质量排序为主线。

## 当前工作流

**任务范本 → MiniMax 识别阶段与每次尝试 → 判断阶段目标 → 核对画面与机器人反馈 → 人工筛选与导出。**

- 数据工作台按「含未完成尝试」「证据不足」「已分析阶段均完成」筛选记录，同时显示实际分析区间、模型来源与人工复核进度。
- 「已分析阶段均完成」只描述结果覆盖的阶段，不代表整条录像成功或数据合格。一次失败尝试不会自动排除整条记录。
- 尚无结果、服务暂不可用、只有历史模型结果分别显示，不补造 MiniMax 判断。历史 OG 结果不算新的 MiniMax 筛选结论。
- 人工复核后的有效阶段结果参与筛选，并标明「含人工复核」；未经人工核对的显示「模型建议，待复核」。
- 默认按记录编号排序，不再按旧质量分排序。人工保留意向、片段与任务指令继续用于导出。

## 审核界面

- 一组播放器控制相机／3D／联看、逐帧、倍速和拖动。阶段与证据按钮定位同一播放位置。
- 右侧「完成条件」「模型输入」「人工复核」。模型输入直接读取原始请求存档，展示当次画面、反馈摘要、观察范围及缓存复用状态；完成条件展示模型判断，人工复核保存结论。
- 播放器下方常显机器人反馈曲线，可切换 29 个身体关节、左右手各 6 路及 IMU 3 轴（按记录实际通道显示）。曲线、数值、相机和 3D 共用时间轴，点击曲线或反馈事件定位回放。
- 曲线使用当前本机实测值，20 Hz 因果对齐，超过 150 ms 的陈旧读数留空，未做摘要用的中值平滑。它不是完整原始采样率，也不是当时发送的关节数组。MiniMax 接收的是腕部轨迹、下肢运动、手指开合及身体角速度的统计/事件摘要。
- 「模型输入」按请求展示真实存档；最终阶段的本机摘要另行标注。纯视觉请求明确无反馈输入，缺失或损坏存档不由当前数据补造。
- 3D 保留为实测动作回看的辅助证据，不产生数据质量等级。G1 原模型、骨盆相对轨迹、指令对照、实测残影与兼容预览保持可用。
- 未分析记录可以直接回放和填写人工保留意向；从「MiniMax 审核」选择任务范本、分析模式和检查区间后提交。
- 新审核和范本解析只使用 HORIZON-MiniMax，无 OG 回退；历史结果保持来源可追溯。

## 审核页字体规范

唯一排版规范入口：`static/review-type.css`，加载在任务页布局样式之后。当前本机统一使用 Noto Sans CJK SC；其他系统依次回退 PingFang SC、Microsoft YaHei、系统无衬线。普通正文和数值不混用等宽字体，JSON 使用等宽字体。

| 信息层级 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| 页面标题 | 24px / 600 | 当前记录名；极窄屏 22px |
| 当前阶段、弹窗标题 | 18px / 600 | 当前审核对象 |
| 区块标题 | 14px / 600 | 回放、反馈、证据、阶段导航 |
| 正文 | 14px / 400–500 | 完成条件、判断依据、表单内容 |
| 操作与字段 | 13px / 400–500 | 按钮、页签、选择器、指标名称；选中页签 600 |
| 关键数值 | 14px / 600 | 反馈读数，tabular-nums 数字对齐 |
| 辅助信息 | 12px / 400 | 时间、状态、单位、数据说明、来源 |

单位与数值分离，数值不从中间断行；注释使用统一辅助色而非继续缩小字号。同一信息角色不随所在组件或屏幕变成 9–11px。浏览器已读取实际计算样式验证上述层级；当前可见文本没有小于 12px 的字号，左右栏等高且默认摘要无内部溢出。截图与测量见 `workspace/evidence/review-type-20261016/`。
